# AgentCore provisioning scripts

All scripts use Boto3 with the `agente-agente-viajes` AWS profile and `us-east-1` region. `00_deploy.py` is the single public entrypoint; the numbered files are small idempotent modules used by that orchestrator.

## Current architecture

- `01_cognito_identity.py` ensures the UI/platform Cognito User Pool and OIDC discovery URL.
- `11_external_provider_oauth.py` creates the separate external-provider User Pool and shared resource server, plus the Flights and Locations scopes, M2M clients, and AgentCore Identity OAuth providers. Hotels is intentionally omitted until the live demo.
- `14_platform_gateway_oauth.py` creates the platform `gateway.invoke` scope, M2M app client, and Identity provider used by the Harness to call the Gateway.
- `02_gateway_and_targets.py` configures the Gateway's platform OAuth inbound auth and the Gateway role's least-privilege outbound OAuth access. It does not create targets.
- `07_provider_apis.py` creates the Flights, Hotels, and Locations DynamoDB tables, Lambda functions, IAM execution roles, REST APIs, `prod` stages, and deterministic demo inventory. It discovers generated IDs by resource name and stores them in the ignored local state file.
- `12_protect_provider_apis.py` protects the provider REST API methods with Cognito scope validation and attaches Flights and Locations as `OPEN_API` Gateway targets using OAuth.
- `13_add_hotels_gateway_target.py` is retained only as an optional automation helper; it is not part of the prescribed demo, where Hotels is configured through the AWS console.
- `17_print_hotels_openapi.py` prints the exact Hotels inline OpenAPI JSON for copying into the Gateway console; it is read-only.
- `03_harness.py` creates/updates the Harness with Gateway OAuth outbound auth and platform-pool inbound auth.
- `06_ui_frontend.py` publishes the UI, chat API, and Cognito SPA client.

## Provision or reconcile

Run from the repository root. The profile must have permissions to create the project resources in `us-east-1`.

```bash
.venv/bin/python -m pip install -r Scripts/requirements.txt
.venv/bin/python Scripts/00_deploy.py
```

For the demo, Flights and Locations remain connected. Hotels is created as a live integration through the AWS console; do not run `13_add_hotels_gateway_target.py`. `04_test_agent.py` tests the Harness after the Harness endpoint is ready.

### Demo runbook

1. Open the UI, sign in with the demo user, and send: `Quiero viajar de Buenos Aires a Mendoza del 10 al 14 de diciembre. Encontrame una buena combinación de vuelo y hotel`.
2. In Cognito, create the Hotels M2M app client with an autogenerated client secret.
3. Remove any automatically-created `Default` resource server.
4. Edit `External Travel Provider API` and add `hotels.read`; save.
5. In the Hotels app client Login pages, edit allowed scopes and add only `travel-provider-api/hotels.read`.
6. Store the client secret in Secrets Manager as an `Other type of secret` with JSON key `client_secret`; use the name `bedrock-agentcore-identity!default/oauth2/external_travel_hotels_oauth` to match the existing convention.
7. In AgentCore Identity, add an Outbound Auth OAuth client using Custom provider, Client secret basic, the Cognito OIDC discovery URL, the Hotels client ID, and the Secrets Manager secret/key `client_secret`.
8. Add the new Identity provider ARN and Secrets Manager ARN to `agente-agente-viajes-gateway-role`.
9. In the travel Gateway, create a new MCP target with Passthrough disabled, Target type `REST API`, OpenAPI inline schema, and Hotels OAuth outbound configuration. Set the scope to `travel-provider-api/hotels.read`.
10. Synchronize the target, refresh the UI to start a new session, repeat the original message, and compare the result. The Harness itself is not changed.

To print the exact inline schema with the deployed Hotels API URL:

```bash
.venv/bin/python Scripts/17_print_hotels_openapi.py
```

The same validated schema is also kept at `Schemas/hotels-openapi.json` and uploaded to `s3://agente-agente-viajes-openapi-schema/schemas/hotels-openapi.json` for the console demo. The Gateway role has read-only access to that object path.

## Teardown

`99_teardown_project.py` resolves the project resources by stable names and tags in the active account and region. It prints a plan by default and performs no mutations unless `--execute` is supplied. It preserves unrelated workloads and shared account resources, including the AWS-managed DynamoDB KMS key.

```bash
.venv/bin/python Scripts/99_teardown_project.py
.venv/bin/python Scripts/99_teardown_project.py --execute
```
